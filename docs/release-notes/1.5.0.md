# Neon Work 1.5.0 — release notes

Planning now knows about holidays and time off, has its own calendar for picking dates, and makes a report written for other people. It also brings the Planning changes described for 1.4.2, which was never released: editing on the Gantt chart, steps under a task, tasks that run alongside, cancelling and deleting tasks, and plan problems shown where you work.

## Holidays and time off

- **A Holidays note** holds everything about working days. Its **All** section is for everyone: `public holidays: England and Wales` (or Scotland, Northern Ireland: worked out by the plugin for each year, substitute days included), `working days: Mon-Fri`, and any dated day off with its name, such as a closure (`2026-12-29 to 2026-12-31 Office closed`), a one-off bank holiday, or another country's public holidays, which you add each year.
- **People's time off** goes under any other heading: a person as in a task's owners (`[[@Kevin Mulholland]]`, or a first name), then their dates underneath as single dates, ranges (`2027-02-08 to 2027-02-12`) or `every Tuesday`. A project note can add its own in a `## Holidays` section.
- **Where Planning looks:** the project's folder, then each folder above it, then the project's customer or Area folder (also when a property names it, as in a PARA vault: `area: [[Work]]`), then the base folder. So a customer in another country, or an Area such as Work, can have its own, and the base folder holds the shared one. The calendar comes from the nearest note with an All section; time off is gathered from all of them.
- **What changes:** every date Planning works out skips days off: the schedule, the forecast finish, "N working days late", *Write dates…*, ⏳ kept in step, and where a dragged bar lands. A task takes longer when its owner is off (with several owners, a day counts when all of them work). Days off are shaded on the Gantt like weekends, the editor and the issues list name them ("not a working day (Christmas Day)"), and the workload warning counts each person's own working days that week. Weeks view has no dates, so it keeps plain Monday to Friday.
- **A warning** when a plan runs past the last year a Holidays note lists, if it has no built-in public holidays.
- **Settings → Projects** has two new settings: the **Holidays notes'** name (Holidays by default) and **You**, written as in a task's owners.

## The task editor's calendar

- Each date in the task editor (🛫 start, ⏳ scheduled, 📅 due) has a calendar button. The calendar is the plugin's own, so it follows your theme on every device, phones and tablets included, where it replaces the system's date dialog.
- **Greyed:** weekends, public holidays and closures. **Striped:** your own time off, on tasks you own (set **You**). **Orange line:** someone else's time off, named on tap or hover, owners marked as such; while a task has no owner yet, everyone's. **Dashed outline:** the task's planned start and finish.
- Any day can be picked, days off included: picking one with a reason keeps the calendar open with it shown. **Today**, **Clear**, **Close**; Escape closes. On the desktop a date can still be typed.

## The report, for other people

- **Summary first:** forecast (with a Holidays line), the Gantt chart, phases, a new **People** table (each task owner's open and done tasks, days of open work, phases and time off), what needs attention, risks / issues / decisions, workload.
- **Then the detail: the project note itself**, from the top to the end of the section holding the plan's last task, so research and notes kept below the plan are left out. It is a snapshot: the front matter, refine callouts and `%% comments %%` go, headings move down a level, links to the note's own headings point at the note, and task lines lose ids, links, durations and the task tag; their boxes become ☐ / ☑, so the copy never counts as tasks twice in Tasks or Dataview.
- The *Critical path* list and the *All tasks* table are gone (the project note replaces them; the summary still gives the critical path's length), and task ids no longer show in *Needs attention*.

## Smaller changes

- **Graph:** the *Fit* / *Full size* buttons are gone; the graph is drawn at full size and the pane scrolls.

## Also in this release (first described for 1.4.2)

- **Plan problems, named and shown where you work.** A ⛔ that waits for an id no task has (often after folding tasks into a holding task, or a typo), one 🆔 on two tasks, or a dependency loop:
  - the Planning view names the task (for example "pla-gp2 waits for pla-sc2, but no task has that id"), and clicking the line opens the note at that task;
  - the report lists them first under *Needs attention*;
  - the project's card and row on the dashboard and Projects tab show a dashed "plan problems" pill, with the details on hover;
  - in the project note itself, the id or link is underlined while you edit, with the reason on hover. Only the display changes, nothing is written; turn it off with *Underline plan problems in project notes* (Projects settings).
- A loop is now named in order (a → c → b → a) instead of "around" one task, and another project's tasks no longer count as problems of this one.
- **Fixed: new tasks from the note went to the wrong place.** *Planning: new task here* (right-click or hotkey) now puts the task below the line the cursor is on (after a list item's sub-items, at its indent), not at the end of the phase. *New task after this* goes below the task's sub-items, so they stay with their task. A task added to a phase without a cursor goes after that phase's own tasks: a phase heading with sub-headings (## 1. Scope above ### 2. …) no longer sends it to the end of the last sub-section. The editor says where the task will go.
- **Editing on the Gantt chart** (desktop and tablet; phones keep the menus):
  - **Dependency arrows** from the end of each task to the start of what waits for it. Ordinary links are faint; links on the critical path, or from a late task, are strong; hovering a task picks out its own links. Click an arrow to remove that link.
  - **Drag the right end of a bar** to change its length (working days; a task fixed by 🛫 and 📅 gets a new 📅).
  - **Drag a bar** to start it later: it writes 🛫, which now means "not before" for a task not yet done, so everything that waits for it moves too. It can't go before what it waits for (you are told why); dragged back to the earliest it can start, the 🛫 goes.
  - **Alt-drag** from one bar onto another to make the second wait for the first (⛔); the first gets an id if it has none; loops are refused.
  - **Undo** puts the last change back.
- **🛫 start dates hold the schedule back.** Before, an open task's 🛫 date moved only its own bar; the tasks waiting for it didn't follow. Done tasks keep their real start.
- **Steps under a task.** The checkboxes directly under a task — `- [ ]` / `- [x]`, or the `- ( )` / `- (x)` action format — are its steps: "2/4" on its Gantt bar (with a progress line inside the bar), in a Steps column of the List, on its board card and in the task editor. Cancelled steps (`[-]`, `(-)`) and notes such as `[?]` don't count.
  - When every step is done but the task isn't, Planning says so ("Outline scope: all 4 steps are done. Mark it done?"); click to tick it with today's ✅ date. It is never ticked by itself, and the report lists it under *Needs attention*.
- **Tasks inside tasks are flagged.** A `#task` (or 🆔) line indented under another task is a plan problem, listed and underlined in the note: make it a plain checkbox (a step) or move it out to its own line.
- **Tasks that run alongside.** Besides ⛔ (starts when that one finishes), a task can now say `[starts-with:: pla-gp1]` (starts no earlier than that one starts) or `[ends-with:: pla-br1]` (finishes no earlier than that one finishes), with a lag if wanted (`pla-gp1+2d`, `+1w`). They shape the schedule, the critical path and the forecast; a task that starts with another is *waiting* until that one has started.
  - **Task editor:** each entry under *Depends on* has a choice of *after*, *starts with* or *ends with*, and a lag for the last two.
  - **Gantt:** dashed arrows, start to start and end to end. Alt-drag picks the kind by the ends you use: right end onto the other's left half, it waits; left end onto left half, it starts with it; right end onto right half, it ends with it. Click an arrow to remove it.
  - The graph draws them as dotted, labelled arrows; the List shows them under *Depends on*; unknown ids and loops are checked as for ⛔.
- **Fewer buttons.** The Gantt's dependency arrows are always shown (the *Links* button is gone). The *SVG* and *Copy as Mermaid* buttons are gone from Planning and from the Tasks and Projects timelines: the **Report** (a note with the chart, ready to print or export as PDF) is the way to take a plan out of Obsidian.
- **Cancel or delete a task** from the task editor (and the task menu):
  - **Cancel task** marks it `[-]` with today's ❌ date: the line, its steps and its history stay; a cancelled task takes no time in the plan.
  - **Delete task…** (red) asks first, listing what it will do: remove the line and the steps under it, take its id out of the ⛔ / starts-with / ends-with links of the tasks that depend on it (named), and a word if it is a milestone or a risk, issue or decision. The confirmation also offers *Cancel the task instead*.
  - Read-only blocks both; Planning's **Undo** puts the last one back (a deleted task's lines and links). The editor's *Cancel* button is now *Close*, so it isn't confused with cancelling the task.
- **Clicking a bar or a task's name on the Gantt opens the task editor**, as in the Board, Graph and List; right-click gives the task menu.
- **Dates in step with the plan.** *Dates…* is now **Write dates…**, and says what it is: a snapshot of today's planned dates as 🛫 and 📅, which then hold the plan. New, per project, in the Planning tab's ⋯ menu: **Keep ⏳ scheduled dates in step with the plan** (stored as `plan-scheduled: true` in the project note; off by default). Planning then writes each open task's ⏳ as the day the plan has it starting, and updates it whenever the plan moves it (while the Planning tab is open), so the Tasks plugin, the Tasks card and calendars show the current plan. It never touches 🛫 or 📅, waits while you are typing in that note, and writes each note once. A ⏳ in the past no longer counts as overdue in the project counts; only a passed 📅 does.
- **The report's chart matches the screen:** dependency arrows (dashed for starts with / ends with), each task's steps (2/4, with the progress line), and a one-line key under it.
- **Fixed: clicking a bar on the Gantt did nothing.** The chart holds the pointer when a bar is pressed (ready for a drag), so the bar's own click never arrived; a press and release without moving now opens the task editor.
